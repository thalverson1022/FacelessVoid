# T8 Practice persistence compatibility policy

2026-10-24. Recorded before Practice persistence edits. T7’s controlled Missing attempts input was not included in saved setups. Practice writes version 3 so previous version-2 readers reject it without silently dropping the new state. The current reader accepts versions 1/2/3: versions 1/2 default absent attempts to zero; version 3 requires an integer `legendary_missing_attempts` in setup, in the existing UI range 0–99. Invalid or future setup data fails before applying candidate state and leaves fixture bytes unchanged. All prior version-2 carried-item/T3 validation applies to version 3. Adventure remains version 4 with the accepted version-2/3 compatibility policy; no account/global-lives data is added. Run-local buffs never persist. Fixed authored items reload from canonical resources, but custom Practice editor items must remain mutable per-setup copies and match their slot. Practice save/load and the attempts input must not change Adventure ownership, unlocks, attempts or save bytes. Only disposable copied projects and fixture saves are used. This qualification makes no power-loss durability or engine-teardown claim.

Review refinement before further loader edits: validate complete setup/gear/target shapes before applying an explicitly incompatible-revision reset. Keep the established reset behavior for structurally valid incompatible snapshots; do not demand that historical IDs resolve against the current registry. Mutable carried ordinary items also become detached copies, preventing restored Practice edits from changing cached Adventure resources.

All supported Practice versions validate present item/equipment metadata before canonical resolution, including the retained version-1 path. Unknown build codec schemas fail before any incompatible-revision reset; the shared structural preflight does not resolve historical content IDs.
