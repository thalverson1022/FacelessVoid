## Current roll and aggregation contracts

### Generation

The [rarity plan](../project/scripts/systems/gear_generator.gd#L386) is Basic: 1 Basic; Master: 2 Basic; Epic: 2 Basic + 1 Rare; Cursed: 2 Basic + 1 Rare + 1 Basic drawback; Unique: 3 Basic + 1 Rare + 1 Special. Crude and Legendary are fixed-catalog boundaries, not ordinary generated plans. [Chaos](../project/scripts/systems/gear_generator.gd#L197) is four independent outcome selections, Basic-positive/Rare-positive/Basic-drawback weights **5/4/5**, with duplicate IDs permitted and no Special outcome.

[Ordinary uniqueness](../project/scripts/systems/gear_generator.gd#L502) tracks canonical IDs over the whole item, across categories and positive/drawback signs. Chaos passes an empty used-ID set for each roll. Pants Basic/Rare Magic Find may therefore each exist in the pool but may not both appear on one ordinary item. Chaos can repeat an eligible canonical ID. Weight is selection likelihood within the eligible category pool; weight zero is disabled, not a negative modifier. [Catalog lookup](../project/scripts/systems/stat_catalog.gd#L655) returns category metadata and weights. T3 must reconcile Pants' category-specific Magic Find/gold ranges and all new drawbacks without broadening ordinary uniqueness.

[Value scaling](../project/scripts/systems/gear_generator.gd#L759): draw a continuous value from the slot/category range, multiply by rarity, request value_scale and contract-depth factor, then round. Rarity multipliers are **1, 1.75, 2, ±2.5, ±3, 2** for Basic/Master/Epic/Cursed/Chaos/Unique; negative sign only for drawbacks. Depth is clamped **1–12**, scaling linearly **1.00–1.35**; normal reward/shop requests use value_scale **1.0**. Percent/chance values round to **0.01** in decimal units (one percentage point); flat/stack values to integers, positive stacks at least one. Binary Specials always store **1.0** and ignore rarity/depth/value scaling. New Pants/Gloves ranges remain base ranges, not final displayed high-tier ranges. T6 must retain deterministic request keys and provenance fields; changed pool length necessarily changes some seeded outcomes.

### Aggregation and combat

[StatSheet](../project/scripts/resources/stat_sheet.gd#L60) canonicalizes contributions, validates domains, sums numeric raw buckets, applies existing floors, one equipped All Stats factor, and existing per-stat caps. Numeric MULTIPLY modifiers contribute `value - 1` to ordinary additive buckets; legacy Poison multiplier paths are explicit exceptions. [Definitions](../project/scripts/systems/stat_catalog.gd#L158) decide eligibility: All Stats **does not scale flat physical Base Damage** (`base_damage`), but **does scale Base Elemental Damage** (`base_elemental_damage`), as well as eligible percentages/chances/economy/timing. **2026-10-25 T3 correction:** the original T2 prose incorrectly excluded elemental base; [current definitions](../project/scripts/systems/stat_catalog.gd#L165) distinguish the two. This corrects documentation only and retains existing behavior. [Application](../project/scripts/resources/stat_sheet.gd#L362) feeds physical/elemental gear buckets, stack bonuses, proc chances and gold/discount/Magic Find into PlayerStats; talent/derived processing remains in BuildResolver.

Specials are a set with inspection counts, not multiplying per-copy effects: [binary accumulation](../project/scripts/resources/stat_sheet.gd#L70), [All Stats](../project/scripts/resources/stat_sheet.gd#L332), [Double Applied Stacks](../project/scripts/resources/stat_sheet.gd#L316). Thus two All Stats items still provide **×1.2**, not ×1.4/1.44; two Double Applied Stacks items still double once. Enemy denial and player immunity are OR semantics. More slots can let previously competing Specials coexist without changing each Special's magnitude. Ignore-resistance retains its **0.5 physical damage penalty**, and ignore-armor retains its no-Shred restriction.

[Conversion dispatch](../project/scripts/systems/damage_calculator.gd#L143) is explicit: physical-only uses physical mitigation, magical-only magical mitigation, and **both conversions apply physical then magical mitigation**. This is independent of which item was equipped last. [Packet calculation](../project/scripts/systems/damage_calculator.gd#L80) preserves original-type scaling/penalty handling. T3/T9 must cover both flags across legal seven-item combinations; do not implement a guessed last-slot precedence rule or double conversion loop.

[CDR finalization](../project/scripts/resources/stat_sheet.gd#L107) records each affix in display-slot/affix order and computes `factor = product(1 - min(1, raw_i * all_stats_multiplier))`; resolved CDR is `1 - factor`. There is no aggregate balance cap. [Scheduler](../project/scripts/systems/combat_macro_scheduler.gd#L16) consumes the retained factor through TimerMath, not a rounded tooltip sum. Buff duration is an additive eligible bucket with no hard cap; existing timer representability validation still applies. T3/T9 must retain contribution order, finite validation, per-factor saturation and the accepted near-zero/1ms timing behavior. New slots supply more contributions; they do not authorize reinstating rejected caps.

**Inventory economy:** only an equipped inventory-economy Special activates [carried import](../project/scripts/resources/stat_sheet.gd#L45). It imports exactly **increased_gold, shop_discount, increased_magic_find**, including negative occurrences, from each owned carried index. It does not import combat affixes, CDR/duration, triggers/unlocks, inventory All Stats, weapon range or Legendary signatures. A carried Special cannot activate itself. [Collection traversal](../project/scripts/resources/stat_sheet.gd#L22) treats each authoritative occurrence as an owned copy, even if IDs or cached Resource pointers match. Equipped and carried raw economy combine before floors/All Stats; no recursive import or duplicate All Stats pass. T5/T9 must preserve equip/swap/sell/destroy activation and deactivation and same-ID separate copies.

**Proc risk remains open:** [resolver limits](../project/scripts/systems/combat_resolver.gd#L24) are depth **16**, shared root-subtree candidate budget **1,024**. [Budget exhaustion](../project/scripts/systems/combat_resolver.gd#L541) marks combat invalid; partial totals are diagnostics and must never count as winning DPS. Extra retrigger, Shred/Decay and crit-applied effects, shorter cooldowns, longer buffs, Signet conversion and existing Serpent/Cloak/helm effects can interact across more simultaneously equipped items. This is a reachable-density hypothesis, not a measured failure or permission to change limits. T3 specifies interactions; T9 uses bounded legal seven-item witnesses and checks invalid consumers; M10 owns broader earned unusual-build stress.

### What seven slots would imply, and what remains unmeasured

**Analytical inference, conditional on retaining uniform eligible slot sampling:** a preliminary shop draw hits a specified slot with probability **1/5 → 1/7** (20%→14.286%), expected draws **5→7** (+40%). For an ordinary/captain node's one-slot eligibility sample the same 1/5→1/7 applies; both choices target that selected slot. For elite's two distinct eligible slots, target inclusion is **2/5→2/7** (40%→28.571%). Boss eligibility already includes every slot, with each preliminary choice draw becoming 1/5→1/7. Dedup retries, fixed Legendaries, item suitability, prices and player selection mean these are **not exact final displayed-offer probabilities or replacement-time predictions**. Do not model six final shop offers as six independent identical draws without accounting for those paths.

More slots also mean more simultaneous numeric affixes, additional Special coexistence, increased gold/Magic Find/discount opportunity and lower cooldown factors. Initial filling can increase total power even if replacing one occupied slot becomes less frequent. Unchanged gold/reward frequency/rarity is the comparison baseline, not proof of equivalent difficulty. No acquisition timing, first full equipment checkpoint, shop spending/hoarding curve, earned DPS trajectory or seven-slot proc-budget headroom has been measured here.

T10's focused comparison should identify the actual seven-slot selection policy and reset loadout, use a small agreed set of matched seeds/routes/roles, and record encounters/contracts to first fill and replacement, eligible offers versus chosen items, purchases/sales/rerolls, gold/stash/inventory pressure, reward tier/depth/Magic Find and combat validity/power. T11 records revision, user progression feel and UI comprehension. Review that evidence before changing tables; do not silently resume D099's exhaustive matrix.

## Economy and proc findings carried forward

**Unresolved discount/resale profitability is confirmed as a formula risk.** At 60% discount, Basic purchase is `floor(18×0.4)=7`, resale9: **+2g gross**; at ≥100% discount a nonzero item still costs1 and resells at its normal tier value. More generally a discount above 50% can produce positive gross spread depending on rounding/tier. At exactly50%, even-priced ordinary tiers break even before other costs; rounding can change the first profitable discount increment. This is arithmetic from current code, not an observed infinite-money run. Offer supply, reroll cost, storage, unlock/ownership and available gold constrain realized profit. No safety claim or automatic nerf follows.

Pants add a Rare discount roll and an inventory-economy Special in the confirmed inputs; both new slots add gold/Magic Find opportunities. Under current formulas, equipped All Stats can amplify eligible equipped+carried economy buckets once, while three carried copies remain the storage ceiling. T3 records exact legality/weights and preserves semantics; T9 verifies ownership transitions and price/reward recalculation; T10 assesses attainable gross/net trades and pacing. Broad economy qualification remains M10 scope. New slots do not import stored combat procs, but economy-derived combat outputs still matter.

Proc-budget conclusions are limited to the source contract above. Increased legal coexistence is the reason for bounded T9 tests; this audit neither proves exhaustion reachable in earned play nor proves safe headroom. Keep existing depth/candidate limits and invalid-result handling. Preserve accepted Exsanguinate1×, Signet1.5×, Wingjammer and Crown values from the M8 handoff until a reviewed change.
