# T8 Adventure persistence compatibility policy

2026-10-24. Recorded before T8 Adventure persistence edits. This expands the [accepted T7 policy](P6M8_T7_Save_Integration_Policy.md), the [T5 acquisition/persistence contract](P6M8_T5_Legendary_Mechanics_Specification.md#acquisition-persistence-and-mode-contracts), and the T8 qualification scope under D080. It records implementation validation choices within that scope; it does not claim new user approval.

Adventure continues writing version 4 in its existing slot, with no new persisted fields or format bump. Current versions 2/3/4 retain their current build codec, numeric gear values, pending offers, run state and run-local Coin flag. Absent Coin flags default to locked in all supported versions; a present flag must be boolean. Version 2 retains the existing exclusion of inline T3 stat identities; versions 3/4 accept their validated canonical identities and exact values. Load does not rewrite supported input files.

Round-trip comparison uses the writer's full-precision JSON representation. Inherited generated-route metadata can contain packed arrays in memory; JSON restores their values as ordinary arrays. This expected container normalization is not loss of numeric values or route state and does not warrant a production format change.

Packaged fixed authored gear resolves by stable ID to the current approved resource, including all sixteen Legendaries. This intentionally adopts current fixed affixes and signatures. Authored resource paths resolve only within the existing packaged allowlist. Missing/deleted/unresolvable gear and obsolete pre-source-kind runtime gear retain the existing drop behavior and notices; valid gear in an old equipment field retains the existing migration to its canonical slot and duplicate-slot drop behavior. No new ownership or Coin-eligibility filter is applied while loading old state. Transactions remain responsible for rejecting stale offers.

Saved JSON is a trust boundary. Before casting, present gear metadata must have its declared primitive/container type; affix validation remains version aware. A malformed slot value such as a string, array or dictionary fails the load rather than being coerced to Weapon or throwing midway. Integer enum values retain the existing valid-slot/tier/source checks and drop policy. Non-string resource paths are malformed and fail atomically, including paths in non-gear pending/active contract data. An allowed path resolving to another resource class cannot be treated as gear; it retains the existing unresolvable-gear drop behavior. Stable IDs do not bypass malformed path/type validation. Run counters, typed array members, history rows and contract discriminator/path fields must likewise have the types their decoder consumes; absent optional fields retain their previous defaults.

Current-version validation and decoding happen on detached candidate state. Invalid JSON, malformed fields, invalid builds/stat identities and unsupported future versions preserve live state, its signals and input bytes. Supported-version primitive run/gear/build-envelope preflight occurs before the historical incompatible-revision reset branch too. Build preflight checks the existing codec's required fields and primitive/container types, without requiring old IDs or allocation semantics to resolve in the current registry. Legitimately incompatible supported envelopes retain their existing explicit reset policy, while malformed ones are preserved. Gear-location context checks include metadata on path-only and stable-ID-only entries, so canonical resolution cannot bypass primitive validation. The existing explicit version-1 policy remains: the current Adventure registry refuses and preserves the file; an explicitly selected historical compatibility registry may retain its existing reset behavior. Legacy `user://save.json` is outside the current Adventure slot and is never migrated or deleted by these checks. Tests redirect every save to disposable copies and verify unrelated sentinel bytes.

The nested build codec remains schema 1 for every supported Adventure envelope. An unknown nested build schema is refused before the incompatible-revision reset path as well, preserving future build data without attempting current ID resolution. The previous version-3 reader must refuse version 4 without altering live state or the fixture; T7 already provides a pinned reader and evidence, and T8 retains/rechecks that evidence separately. [Practice persistence policy](P6M8_T8_Practice_Persistence_Policy.md) owns the isolated Practice envelope and missing-attempt input. Normal temp-file replacement remains the inherited write mechanism; power-loss durability, account persistence, loot redesign, balance acceptance and broad generated-route format redesign are not claimed.
